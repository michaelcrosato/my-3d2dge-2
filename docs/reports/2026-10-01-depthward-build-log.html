In short

You asked for a complete hack-and-slash game that shows off the engine. You wanted a deep skill tree, a Path of Exile 2 or Diablo IV style loot loop, one named mechanic per level, a town, difficulty sliders, endless procedural content, and AI-agent tools built into the engine. Depthward now has all of that.

The work happened in two stretches: about an hour and a half on the evening of September 30, then from 10:04 to about 18:00 on October 1, with one pause of about 50 minutes. Every change followed the same routine. It ran the tests, checked the offline build in three browsers, and went through a pull request and GitHub CI before being merged, as you asked.

The early pull requests laid foundations and were large. After that came many small ones. Each one fixed something a measurement found or added a feature the brief called for.

What we built, and why

Grouped by theme rather than by date. Each group opens with the reason it exists. The PR numbers link to the full write-ups on GitHub, which list every check that was run.

4.1 The foundation

WhyThe brief asked for a complete game that scales forever. So the game is built from data “vocabularies” that combine: stats and modifiers, skills as timelines of effects, statuses, monster parts, items and affixes, the tree, themes. New content is mostly new data, not new code. The simulation is also deterministic: 60 fixed steps per second with a seeded random generator, so the same inputs always give the same result. That decision paid for itself later. Bots can playtest, tests can check exact outcomes, and replays work.

#5

The ARPG core (13,876 lines)

Combat with strikes, projectiles, zones, chain lightning, buffs, summons, telegraphs, i-frames and cancel windows. Monster AI built from behaviour archetypes that share one pathfinding field, elite affixes, bosses with phases and enrage. Loot, breakables and chests. A tree of about 550 nodes. Nine dungeon themes with procedural layouts. The town and its NPCs. Creature genomes across eight body plans.

On the rendering side: procedural creatures with procedural animation, a pooled dynamic light system (torches, projectiles, explosions, loot beams, the hero's lantern), dithered wall cutaways around the hero, VFX, engine-rendered item icons, and a pixel-font overlay with damage numbers, labels and a minimap. Controls work with keyboard and mouse, gamepad with twin-stick aim, and touch.

43 tests · offline build passed in Chromium, WebKit and Firefox at phone size · 24 of 24 screen layouts clean

4.2 Level mechanics and the campaign

WhyThe brief: one mechanic per level, named after it, combined later. Casual players must be able to ignore it and speedrunners must be able to exploit it. Each mechanic is optional, and kills it causes (“trick kills”) give +50% XP as the reward for learning it.

#6

13 mechanics, a named campaign, endless depths

Blast Kegs, Spike Traps, Shrines, Launch Pads, Black Ice, Lightless, Rolling Boulders, Rift Gates, Fire Vents, Totems, Gravity Wells, Chrono Fields and Loot Imps. Depths 1–13 introduce one each and are named after it. Depths 14–24 are authored combinations such as “Kegs on Ice” and “The Gauntlet”. Beyond that, a generator draws two or three mechanics, a theme that suits them, palettes and procedural species from the depth's seed, and builds a title from the mechanics' names.

#43#44

A 14th mechanic: Storm Pylons

Strike two pylons near each other and lightning arcs between them, shocking monsters that cross the beam. It is introduced at depth 25 and named after it, keeping the one-mechanic-per-level rule. The bot learned to use it: mechanic kills per run went from 0.3 to 1.3.

The careful part was not breaking existing content. Adding a mechanic to the list would have reshuffled every endless depth and every Daily Trial. Instead, endless and daily draws still use the original 13, and later mechanics swap into about a quarter of draws. Only 23% of depths 25–400 changed, and that day's trial stayed the same.

4.3 Tools for AI agents

WhyThe brief asked for agent tools built into the engine that “help build assets and somehow inspect them”, and to “show them the way”. They served two purposes. Future agents can build content with them, and I could measure the game instead of guessing. Many fixes in this report started as a tool measurement.

#7

Tool registry, command line, MCP server, autoplayer bot

Each tool has typed parameters, validation, defaults and a worked example. The groups cover catalogs, creature genomes, custom species, monster and item inspection, loot simulation, level generation with maps, the tree, hero builds, balance curves, bot playtests, renders and live-game control. They are reachable from the page (window.agent), from a terminal (npm run agent) and as an MCP server (npm run mcp). The autoplayer bot explores, fights, dodges, loots and uses mechanics. It also powers Autopilot in the pause menu.

#19

An agent-discoverable web build

In browsers with WebMCP, the page registers 40 of its tools for an in-browser AI assistant (40 is Lighthouse's recommended maximum). llms.txt and an AI catalog describe the game to agents.

Lighthouse agentic browsing 50 → 100 · SEO 82 → 100 · best practices 96 → 100

#36#38#45#52

Design tools: skills, uniques, themes, species

skill.test casts any skill at dummies and reports what actually landed. unique.design prototypes a unique item and ranks its power against existing ones. theme.design builds a dungeon look and walks the hero into it. species.design returns a share code a player can paste into the Workshop, so an agent can hand a creature to a person.

#29

Every tool proves its own example

Calling all 42 tools from their own documentation found three without examples, so agents copying from help got errors. A test now requires a working example for any tool with required parameters.

4.4 Balance by measurement

WhyThe brief said “challenging, but don't worry about overtuning”. Without human playtesters, the autoplayer bot played the campaign and reported deaths, clear times, boss fight lengths and how low its life got. Each change below came from a number.

#8

First balance pass

Before: hero damage grew about 28,000× from level 1 to 85 while monster life grew about 860×. Bosses fell in 0.5–3 seconds from depth 8. A fresh hero died twice to the first boss, and depths 22, 24 and 34 could not be cleared. Fixes: monster life ramps with the hero's growth, early bosses are eased, and an XP catch-up applies. Mechanics can no longer trap a player who ignores them: gravity-well pull is capped, bosses ignore launch pads, and totems heal bosses slowly.

After: no failed depths in 40 · first boss about 25 s · 0.3 deaths on average at depth 1

#10

Thorns stopped killing strong heroes

The thorns affix reflected 15% of the hero's own hit, so a strong hero killed itself. Bot runs at depth 80 died about 45 times in 400 seconds. The reflect is now bounded.

Depth 80: 0% clear, ~45 deaths → 100% clear, 0 deaths

#26

Tension back in the mid and late game

A later check found the game had become a power walk: no deaths in 40 depths, and the hero rarely dropped below 75% life. Monster damage now rises 1.2% per level past 12, capped at +80%. The opening is unchanged.

Melee, depths 11–20, median lowest life: 0.78 → 0.61

#31

Harder presets, explained

On Hard the bot died 3 times in 20 depths. On Nightmare it died 12 times, half of them to the depth-1 boss. That is fair for an opt-in preset, but nothing told players what they were choosing. Each preset now has a one-line note in the pause menu.

#36#37

Skills measured, minions fixed

skill.test's first run found Spirit Wolves doing 56 damage per second against a basic Slash's 1,751. Hero minions used the numbers tuned for monsters hitting the hero, and enemy pact buffs leaked into them. They now hit on the hero's spell curve: 419 per second at level 30.

A sweep of all 22 hero skills then trimmed Flame Surge (2.7× Fireball, because recasts stacked) and Molten Strike (1.9× Cleave), and buffed Ice Spear.

#39

Uniques that stay worth wearing

Only 26% of uniques were upgrades at level 60, because their fixed lines don't grow with item level. Uniques now also roll three regular affixes, the Diablo IV pattern: the powers define the build and the affixes keep the item competitive.

Upgrades at level 60: 26% → 43%

#35

Smarter auto-builds

The auto-builder behind bots and Autopilot spent points on enhancements for skills that weren't on the hotbar. It no longer does.

4.5 Creatures: the “think Spore” brief

WhyYour example was Spore: build the base system traditionally, then make it modular and procedural so it feeds endless content. Creatures are where that shows most.

#9

The Creature Workshop

An editor (from the title screen, or from Sela the Beastwright in town) for body plan, proportions, legs, heads, horns, tails, spikes, wings, palette, behaviour and attacks, with a live preview at the game's pixel density. Parts set the stats: bulk gives life and slows the creature, horns and spikes give damage, legs and wings give speed. A threat budget keeps outliers in check. Released designs join the dungeons from depth 2, and the Proving Grounds let you fight your design and its matriarch.

#16#50

Pinnacle bosses every tenth depth

Eight named bosses assembled from existing parts: The Hollow King, Mother of Cinders, The Glass Choir, Vael Unbound, Grull the Mountain, The Brood Tyrant, The Frostshell Matriarch and The Rot Colossus. Each has a title, an attack kit, adds and a guaranteed unique drop. Scorpion tails were fixed to curl over the back. A serpent design was dropped because it read as a pale tube at boss size.

#51#52

Share a species as one line of text

Half of Spore's fun is sharing. A species now fits in a code of about 225 characters (DW-SPECIES:…) that can be copied and imported. Codes go through the same checks as saved designs, so broken ones are refused.

4.6 The loot and progression loop

WhyThe brief named Path of Exile 2 and Diablo IV. Those games run on chase items, build-defining powers, endgame levers and reasons to come back each day.

#33#55

49 uniques, and a smith that works on them

24 uniques were added so that every item base has at least one. They include starters that hint at a build, skill uniques (an extra Fireball, two more Chain Lightning chains) and play-style uniques (after a dodge, at low life, against bleeding enemies). The blacksmith can now reforge and temper a unique's regular affixes, the way Diablo IV's enchanting works.

#34

Four new skills

Lacerate, Knife Rain, Flame Surge and Molten Strike evened out the tree's sectors, giving 21 active skills and 575 nodes. New clusters were added only where no existing node id shifts, so saved heroes keep their allocations. I checked this by comparing the tree before and after.

#12

Pacts

Eight risk-for-reward modifiers chosen at the waypoint, in the spirit of Diablo IV's sigils and Path of Exile's map mods. Examples: Brutal (+40% monster damage), Teeming (+50% packs), Eclipse (darkness). Each pairs one readable risk with more XP, rarity or gold.

All eight at depth 10: 30% clear rate, 161 items, 26.9k XP (vs 100%, 70, 11.3k without)

#13#14

Upgrade arrows and a loot filter

A green arrow marks bag items that would make the hero stronger. It uses the same power measure the bots use to pick gear. A loot filter hides labels for plain items, which were almost half of all drops.

#17#21#40

Codex, Daily Trial and Records

The Codex collects species slain (with portraits), uniques found and pinnacles defeated. The Daily Trial is one seeded challenge per day, the same for everyone, with a best time for speedrunners and a first-clear hoard for power-levelers. Records gather deepest depth, fastest clear, bosses slain, deaths and time played.

4.7 Sound and music

WhyThe game had no sound at all. I kept the project's generated-from-code approach: no audio files and no licences to track.

#11#15

Synthesized effects and generative music

53 sound recipes are synthesized live and mapped to game events, quieter with distance and panned across the screen. Each theme has an ambient drone. The music is composed bar by bar in four moods (town, dungeon, dark, boss) and follows the game, switching to the boss mood when an awake boss is near. audio.inspect renders a sound as a waveform and spectrogram, so an agent can “see” what it can't hear.

Levels were set by measured peak and RMS; nobody has listened to it yet

4.8 Replays and ghost racing

WhyBecause the simulation is deterministic, a whole run is described by its start and the player's input on each frame. That makes replays tiny and exact. It is a strong engine showcase and something speedrunners want.

#41#42

Replays you can watch and share

Each save slot keeps its best run per depth and per Daily Trial. Watching one re-simulates it frame by frame, then compares a fingerprint of the final game state with the recorded one and shows “✓ Frame-exact”. Runs can be saved as files of about 12 KB for a 33-second clear and opened in another browser session. A run where the build changed mid-depth isn't kept, because it couldn't be reproduced.

#56

Race your best run's ghost

Your best run plays in a second simulation beside you, drawn as a translucent pale-blue figure, and a toast tells you when it would have cleared. The first build of the ghost was invisible. Copying the hero's materials dropped a small shader addition the renderer needs, so the draw calls failed. That is now fixed, with a test so it can't silently come back.

A run recorded with the ghost beside it still replays frame-exact · a simulation step costs about 0.13 ms

4.9 Performance and stability

WhyThe game has to survive phones, long sessions and a single-file download. These changes kept the look identical while cutting cost.

#18#20#30

Smaller models at the same pixels

Characters are drawn about 48 art pixels tall, so most mesh detail never reached the screen. Meshes were simplified from 129k to 47k triangles, with no visible difference at game resolution. Textures went from 512 to 256 px with 0.0% of pixels changed. Models were then packed losslessly, and renders before and after were byte-identical.

Busy depth-80 frame: 618k → 252k triangles · offline build 23.7 → 10.7 MiB

#24

GPU memory no longer climbs

A four-minute Autopilot soak showed GPU textures growing from 157 to 1,043 over eight depths, which ends in a crash on a phone. Each character's skeleton and materials were never freed on level change. They are now freed, and the offline-build verifier fails if memory grows across reloads.

#27#54

What you see is what happened

Agent captures after a headless run showed 32 white wedges around the hero: every slam from the run, drawn at once. Effects now start at their true age. Separately, in WebKit a single redraw while paused could stay off screen, so a change while paused now draws two frames.

4.10 Player experience, accessibility and phones

WhyA complete game has to be learnable and comfortable on every device. These came from walking the new-player flow and checking layouts on phones, tablets and wide screens.

#23

Save slot 1 could be overwritten

The title screen's backdrop used a throwaway hero, and it saved itself into slot 1. A player who started a real game in slot 1 lost it to a fresh level-1 hero on the next launch. Throwaway heroes no longer save, and leftover phantom saves are cleaned up. The same PR added first-steps hints that name the right control for the device in use.

#28

A full map

Tab, or tap the minimap. It shows every explored room, the exit, chests, shrines, NPCs, the boss and good loot. A seventh toolbar button for it collided with the Skill 5 touch button on an iPhone SE, so the minimap itself became the button.

#22#32

Comfort and colour-blind options

A screen-shake slider (it starts at zero when the system asks for reduced motion), a damage-number toggle and richer controller rumble. Bold telegraphs turn enemy attack warnings magenta with a white outline, because red is hard to see on brown and green floors for red-green colour-blind players.

#25#46#47#48#49

First minutes and phone polish

Hints wait for the arrival banner. Touch controls no longer show through the title screen. New heroes see the depth list before the Daily Trial. The title text is readable. Tapping an item on a phone scrolls its details into view. Passive-tree labels no longer print over each other.

#53

Photo mode

From the pause menu: the game freezes, every piece of UI hides, and Save image downloads the exact pixel art at about 2,400 px wide. Pixel/3D and palette can be switched for the shot.

How every change was checked

Your instruction to push and merge every commit meant main had to work after every merge. So each change went through the same routine, in this order:

  1. A branch of its own (agent/…), so each change can be reviewed and reverted alone.
  2. npm run check: typecheck, production build and the automated tests (26 at the start, 126 now). Meaningful logic changes added a regression test that fails without the fix.
  3. For anything that runs in the game: rebuild the offline single-file version and run its verifier in Chromium, WebKit (Safari's engine) and Firefox. It plays title → town → touch controls → rebinding a key → panels → merchant → a fight in depth 1 → render modes. It fails on any console error, any network request, or GPU memory that grows across reloads.
  4. For UI changes: screenshots on small phones, foldables, tablets and ultrawide screens, iPhones in WebKit, then looking at them. Screenshots stay outside the repository.
  5. For balance or performance changes: before and after numbers from the agent tools, written into the PR.
  6. Commit, push, open a PR that says what changed, why, which checks ran and what wasn't covered. Wait for GitHub CI (and the Vercel preview build), merge, update the local copy.

Mistakes and corrections

Things I got wrong along the way, and what happened to each:

  • The commit for #39 claimed about 40% of uniques became upgrades before I had measured it. The measured figure was 43%, and I corrected the PR description to say so.
  • The ghost was invisible in its first build. Screenshots caught it before it was committed.
  • The Workshop's import button first went inside a group that is collapsed for new players, so they couldn't see it. It moved to the action row before merge (#51).
  • A map button in the toolbar collided with a touch button on small phones (#28).
  • A serpent pinnacle boss looked wrong at boss size and was replaced (#50).
  • A Daily Trial test assumed a level's mechanics always equal the trial's list. A dark pact adds one, and the test was corrected (#43).
  • The agent instructions file said there were 42 tools after there were 46. Fixed in #56.
8

Not yet verified

These were not checked, or were checked only in part:

  • Real iPhones. iOS Safari isn't available on this machine. WebKit with iPhone screen sizes was the closest check.
  • Human players. All balance numbers come from the autoplayer bot. Its footwork is simple, so it overstates melee deaths and understates ranged ones. Spell builds stay quite safe late, and Nightmare's first boss is harsh.
  • How it sounds. Sound and music levels were set from measurements; nobody has listened yet.
  • WebMCP in a real browser. The installed Chromium didn't expose it yet, so it was tested against a stand-in that follows the documented API.
  • Replays across browsers. Replays and ghosts are exact within one browser engine and game version. A run from Chrome may desync in Safari, by design.
  • Phone performance. Lighthouse performance (about 40) was measured with software rendering here. It needs a real device.
  • Rumble. It needs a physical gamepad and wasn't exercised.

Glossary

Pull request (PR)
A proposed change on its own branch, with a description, that is checked and then merged into main.
CI
Continuous integration: GitHub runs the checks on every PR before it can be merged.
Deterministic simulation
The game logic runs in fixed 1/60-second steps with a seeded random generator, so the same start and inputs always produce the same result.
Seed
A number that fixes what the random generator produces, so a depth or a Daily Trial is the same for everyone.
Offline build
standalone/3dpixel2d.html: the whole game in one file that runs without a network.
WebKit
The browser engine behind Safari. It is used here to approximate iPhones.
Agent tool
A function an AI agent can call to inspect or build parts of the game, such as rendering a creature or running a bot playtest.
MCP / WebMCP
Model Context Protocol: a standard way for AI assistants to call tools. WebMCP is the in-browser version.
Bot / Autopilot
The built-in autoplayer. It plays depths for balance measurements, and players can switch it on from the pause menu.
Affix
A rolled stat line on an item, such as “+40 life”.
Unique
A named item with fixed special powers that can define a build.
Keystone
A passive-tree node that changes a rule of the game rather than adding numbers.
Pact
An optional modifier chosen at the waypoint: more danger for more reward.
Pinnacle
The named boss at the end of every tenth depth.
Telegraph
The marked area that warns where an attack is about to land.
Trick kill
A kill caused by a level mechanic (a keg, a pylon, a boulder). It gives +50% XP.
State hash
A short fingerprint of the whole game state. If a replay ends with the same hash as the recording, it reproduced the run exactly.
